# API and Event Contracts

## Conventions

- Prefix: `/api/v1`.
- JSON request and response bodies.
- Bearer access token for authenticated endpoints.
- `Idempotency-Key` for sensitive commands.
- `X-Request-ID` accepted from trusted callers or generated by the API.
- Cursor pagination for large lists; simple page pagination is acceptable for the MVP admin UI.

The public routes are served by the User and Admin Gateways over HTTPS/JSON.
Socket traffic is served by the Socket Gateway over WSS/WebSocket. Gateways
translate public contracts into private service gRPC contracts; services do not
own public HTTP APIs. The frontend never calls a service directly, and public
paths and response contracts remain stable.

Error envelope:

```json
{
  "error": {
    "code": "BOOKING_SLOT_UNAVAILABLE",
    "message": "The selected court is no longer available.",
    "request_id": "req_123"
  }
}
```

## Authentication

The internal synchronous contract for these routes is versioned in
`contracts/proto/identity/v1/auth.proto`.

```text
POST /api/v1/auth/register
POST /api/v1/auth/login
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
GET  /api/v1/me
```

## Customer Booking

```text
POST /api/v1/bookings/holds
POST /api/v1/bookings/{booking_id}/payments
POST /api/v1/bookings/{booking_id}/cancel
GET  /api/v1/bookings/{booking_id}
GET  /api/v1/bookings/me
```

Create hold request:

```json
{
  "court_id": "court_uuid",
  "starts_at": "2026-07-20T12:00:00Z",
  "ends_at": "2026-07-20T13:00:00Z"
}
```

The API calculates availability and price. It does not accept a client-calculated amount.

## Initial Domain Events

Event envelope:

```json
{
  "event_id": "event_uuid",
  "event_type": "booking.confirmed.v1",
  "occurred_at": "2026-07-20T10:00:00Z",
  "organization_id": "organization_uuid",
  "aggregate_id": "booking_uuid",
  "correlation_id": "request_or_workflow_id",
  "payload": {}
}
```

Events:

- `booking.hold_created.v1`
- `booking.hold_expired.v1`
- `booking.confirmed.v1`
- `booking.cancelled.v1`
- `booking.checked_in.v1`
- `payment.succeeded.v1`
- `payment.failed.v1`
- `refund.created.v1`
- `notification.requested.v1`
- `payout.created.v1`

Compatibility rule: published event fields are additive within a version. Breaking changes require a new event version.
